# Changelog

All notable changes to this project are documented here. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed
- Asking: the Draft is cut at its handles in core. The `delta` event's contract changes: `DeltaEvent` carries `pieces` instead of `text`, each `{"text": …}` or `{"handle": n}` (`TextPiece`, `HandlePiece` in `asking` and in the API's schemas). `DraftCut` reads the handle grammar `resolve_answer` reads, now defined once in `asking.handles`, so a bare `[13]` on a Seed that numbers no Reference shows as a chip while streaming; a handle the Conversation does not know is left out. The web app renders the pieces and its own copy of the grammar (`answers.Draft`) is gone; the CLI prints handles as `[#n]`. CONTEXT.md gains Draft.

### Added
- Resolution: the optional `verify_dois` Stage, between `extract_citations` and `resolve`, asks doi.org's Handle API whether each printed DOI is registered. It is free and keyless, runs 10 requests at a time (`PE_DOI_ORG_CONCURRENCY`), and caches its verdicts in `registry_responses` (migration `0006`, source `doi:handle`). Offline it still ends `done`, with a warning and the unverified DOIs counted; a rerun asks only about those. `resolve` resolves a Reference with an Unregistered DOI as if no DOI were printed, and the side panel marks DOIs registered or unregistered. ADR 0012 amends ADR 0011. CONTEXT.md gains Unregistered DOI. The measurements are in `docs/research/2026-11-doi-existence.md`.
- Resolution: Registry Checks (ADR 0011). `resolution.registry_check(conn, citing, refs, registries, refresh=)` runs the local pass (after the Library sync the caller runs), then asks Crossref and OpenAlex only for what neither the Library nor the cache answers, layer by layer (DOI batches of 100 to both at once; OpenAlex `title.search`, five candidates; Crossref `query.bibliographic` on the printed string), and yields each Reference's Resolution as it lands, then `RegistryCheckFinished` with its counts, or `BudgetSpent` when OpenAlex's day is spent. Crossref decides which Work a DOI is; a DOI only OpenAlex knows (DataCite, arXiv) comes from OpenAlex; APA's `//` form finds the single-slash record; a `posted-content` preprint is its own Work. A bibliographic hit is `low`: its whole title printed with its first surname or year. `Registries` holds one limiter per host (Crossref list queries 1/s, 1 at a time, or 3/s, 3 with `PE_CROSSREF_MAILTO`, tightened by `x-rate-limit-*`; OpenAlex 8/s, or 25/s with `PE_OPENALEX_API_KEY`), waits out a 429's `Retry-After`, backs off on a 5xx, and gives up after three tries (`RegistryError`). Every response is kept in `verify_dois`' `registry_responses` table (misses asked again after 30 days, hits until `--refresh`; migration `0007` adds the layers), an Unregistered DOI is never sent, a Reference the Library matches at certain or high is never sent, even on `--refresh`, and a 429 holds back every call to its host, and the `resolve` Stage reads it, so a re-run keeps what a Check found. A Work a registry found gets a `works` row with its metadata and no `synced_at`. Layers `crossref` and `openalex`; `counts` reports Unresolved References. CLI: `paperexplorer check <zotero_key> [--reference <key>] [--refresh]`, which syncs the Library first.
- Resolution: every Library Item is a Work, kept current by the Library sync (Zotero's `since` protocol; the whole Library on the first sync, then only its changes, trashed and deleted items included; the last copy stands when Zotero is unreachable), and the `resolve` Stage matches every Reference of a Work against it, with no registry call: a printed DOI that agrees with the Reference is `certain`, an exact title with surname or year (or an equal main title with both) `high`, a near title `low`. A DOI whose record the printed title does not agree with is a DOI Conflict: the title decides, at `low`, and the DOI's Work is kept as the other option. Duplicate Items (two Library Items with one DOI) each get a Work row; the Standing Item is the one the reader let stand, else the one with a PDF, else the older (amends ADR 0007). CLI: `paperexplorer sync` (a full read), `paperexplorer duplicates [--stand <key>] [--merge <keep> <other>]` (merges in Zotero as Zotero desktop does, after asking) and `paperexplorer resolutions <zotero_key> [--low]`. Migration `0005` (pg_trgm, `library_sync`, `resolutions`). `GET /works` lists only Works with a Stage run. Settings `PE_CROSSREF_MAILTO` and `PE_OPENALEX_API_KEY`, empty for now. CONTEXT.md gains DOI Conflict, Reader's Choice, Duplicate Items and Standing Item.
- Asking: `AnsweredEvent` and `ErrorEvent` carry the turn's accounting: `model_requests` and `tool_calls`, the model's own (a redraft's request counts, the forced search does not), counted as each is made so a failed turn keeps them, and `forced_search`, the forced search's ranked Chunks (None reading the whole Seed). The CLI's `ask` and the eval read them from the event instead of counting `ModelResponse`s in the Conversation, and the eval's hit@8 no longer runs the search again. The trace's `model_requests` and `tool_calls` scores are the same counts, so a failed redraft's request now counts. The API's events are unchanged.
- Docs: the design for resolving References (`docs/design-resolution.md`): the Library synced as Works and matched first, Registry Checks against Crossref and OpenAlex only when the reader asks (ADR 0011), a cache so no DOI or query is sent twice, duplicate DOIs chosen or merged; the measurements behind it in `docs/research/2026-10-doi-resolution.md`; CONTEXT.md gains Library, Registry Check and Unchecked Reference, and Unresolved Reference now needs a Check.

Verdicts are keyed by Question, mode and repeat (`Verdicts.share(mode, repeat)`); summaries and verdicts of runs that asked once read as repeat 1.
- Eval: run `20261031T140751Z-a758bbc`, the first with whole-Seed answering live, judged (`docs/eval-2026-10-31.md`): its summary and verdicts in `evals/runs/`. Every Answer of an eval run is judged against the Seed, grounded and correct with a note, in `evals/runs/<run id>.verdicts.yaml` (the judge's words only), with each Pointer's place read for aptness; `paperexplorer.evals` loads them, holds them to the run's summary and posts them as Langfuse scores `judge.grounded` and `judge.correct` on each turn's trace (`scripts/post_verdicts.py`, `eval` environment). `Tracing.score_trace` scores a trace by its id; scoring it again replaces the verdict. - Eval: the harness for the eval of asking the Seed. `evals/seed-questions.yaml` holds 22 Questions written from the parsed Seed (its measurements, methods, shortcomings and follow-ups, and five it does not answer), each covered one with the places, Heading Path and page, a good Answer points at, as a pydantic-evals dataset. `paperexplorer eval <zotero_key>` asks each in a fresh Conversation as the reader does and, as a baseline, with the whole Seed in context; traces go to Langfuse's `eval` environment tagged with the run id. It measures hit@8, Pointer coverage and Support, Pointers on expected places and their cosines, exact Quotes checked against the printed text, whether uncovered Questions are said to be uncovered, model requests, tool calls and latency, and checks the design's bar. - Web: the Conversation sidebar. A Work's page shows the sidebar left of the reader (a drawer below 92rem) with a legend of its two marks. A Question posted there streams through the web app (`POST /works/{id}/questions`, then `GET /questions/{id}/stream`, which relays the API's events as HTML for htmx's SSE extension, vendored at 2.2.4): the tools the model runs, the draft with its handles as placeholder chips, then the resolved Answer in its place, earlier Questions and Answers kept above. - API: Conversations. `POST /works/{id}/conversations` starts one about a Work whose Chunks are embedded (404 unknown Work, 409 not yet chunked or embedded); `POST /conversations/{id}/questions` streams a Question's turn as server-sent events (`step`, `delta`, then `answer` with its Pointers and Quotes, or `error`), 404 for an unknown or evicted Conversation and 409 while it still answers; closing the stream cancels the turn. Conversations live in the API's memory, evicted least recently used beyond `PE_CONVERSATIONS_MAX` and after `PE_CONVERSATION_IDLE_MINUTES` unused. Turns run on an asking thread with an event loop and a store connection of their own, so the API stays responsive. `ApiClient.start_conversation` and a streaming `ApiClient.ask` yield typed events. compose passes `PE_LANGFUSE_RELEASE` into the containers; tower-check asks the Seed one Question over the running API and logs its event counts and timings.
- Asking: the answering agent. `asking.ask(ctx, conversation, question)` answers a Question about the Seed with pydantic-ai against Ollama's OpenAI-compatible endpoint (`PE_CHAT_BASE_URL`, `PE_CHAT_MODEL`, `PE_CHAT_API_KEY`, `PE_CHAT_NUM_CTX`) and streams its steps, its draft and then the resolved Answer, or an error. The Seed's map (headings with § numbers, its abstract) and the versioned system prompt are always in context; the server's forced first search goes into the history as the model's own; the model reads with `search`, `read_section`, `read_around`, `reference` and `citing_sentences`; a Chunk keeps its `[#n]` handle for the whole `Conversation`; at most 6 model requests, the last without tools; the model's thinking is traced, never shown or kept. One `question` trace per Question holds the forced search, every model request, tool and embedding call and the resolution, scored with the Answer's counts, tool calls, model requests and latency. `paperexplorer ask <zotero_key> "<question>"` streams an Answer and lists its Pointers and Quotes. `scripts/paperexplorer-chat.Modelfile` and `setup-tower.sh` create the `paperexplorer-chat` alias; tower-check asks the Seed three Questions and logs their counts.
- Asking: `asking.resolve_answer` turns a model's complete draft into the Answer the reader sees: its `[#n]` handles leave the text, each handled sentence gets a Pointer per cited Chunk with close or weak Support (bge-m3 cosine against the Chunk sentences, moving to another Chunk read this turn when only that one is close), and words in double quotation marks are an exact Quote only where a Chunk read this turn prints them (ligatures, line-break hyphens and whitespace folded for matching only), mapped to their place in the block. `Answer.counts()` gives Pointer coverage, Pointers per Support and exact and not-exact Quotes for the `question` trace. Setting `PE_SUPPORT_THRESHOLD` (0.7, provisional until the eval).

- Chunks: `chunking.chunk` cuts a parsed Work's paragraphs and footnotes into Chunks of at most 400 bge-m3 tokens at sentence borders, windows of one paragraph sharing a sentence, flagged `short` or `oversized_sentence`; migration 0003 with the `chunks` table and its English full-text index; the `Chunks` repository; the `chunk` Stage (`paperexplorer run chunk <zotero_key>`), which tower-check runs on the Seed.

### Changed
- Wiring: `paperexplorer.wiring.Wiring` builds tracing, the Embedder and the chat model once from `Settings` and gives each turn its `AskingContext` (`wiring.asking(conn)`); the CLI's `run`, `search`, `ask` and `eval` and the API's `app_from_env` all use it instead of wiring them by hand. The CLI's tests pass a `Wiring` factory as Click's `obj` instead of patching `asking.chat_model` and `OpenAICompatibleEmbedder.from_settings`; `search`, `ask` and `eval` share one find-the-Work-or-exit.
- Eval: `evals/runs.py` split in three: `runs` keeps the run and `write_run`, `summaries` turns a report into its summary and `rendering` writes both as Markdown, pure and tested without Postgres over hand-built reports; the report models join `evals/models.py`. The public names in `paperexplorer.evals` and the rendered summaries are unchanged.
- Asking: reading the whole Seed, the request closes with one user turn, the note that there are no tools, then "The reader's Question:", then the Question, instead of the note as a turn of its own after the Question; the Conversation keeps the bare Question. The prompt version is now `0a13920d8363`.
- Eval: its modes are `live` (as the reader asks: the whole Seed when it fits) and `retrieval` (forced, the fallback); the bar is checked on `live`, with hit@8 from the forced search. `paperexplorer eval`'s `--baseline/--no-baseline` becomes `--retrieval/--no-retrieval`, on by default. Each turn records its reading, and the summary counts each mode's turns by reading. `AskingContext.whole_seed` is gone; committed summaries of earlier runs still read.
- API: `ApiClient` takes any HTTP client with a fitting `get` rather than an `httpx.Client`, since pydantic-ai brings httpx2 and Starlette's `TestClient` then is an `httpx2.Client`.
- `Tracing.span` and `Tracing.score` record a step and a score under the current trace (nothing outside one); `configure_tracing`'s `http` also carries Langfuse's own requests.
- API: `create_app(connections, asking)` takes the asking setup (`Asking`: each turn's context and the Conversations); without it the app serves Works and Citations only. `HttpClient` also needs `post` and `stream`. `app_from_env` configures logging from `PE_LOG_LEVEL` and `PE_LOG_FORMAT`.
- Asking: `PROMPT_VERSION` hashes the agent's notes (`LAST_REQUEST`, `WHOLE_SEED`, `NO_TOOLS`) with the system prompt, so editing a note changes the version too. `PE_SUPPORT_THRESHOLD` stays 0.7, now set from the eval rather than provisional.

### Fixed
- Web: every script and stylesheet URL carries a hash of the file's contents (`?v=…`), so a deploy that changes a file changes its URL and a browser never runs a cached old script beside a new page. A cached `conversation.js` from before the three-pane reader opened and shut the drawer at once and scrolled the window instead of the Work.
- Asking: in a Seed that numbers no Reference, a bare `[13]`, `[13, 14]` or `[13–15]` in square brackets is read as a handle; the model wrote such numbers for `[#n]` in the live app and the Answer got no Pointer. In a numbered Seed `[12]` stays its marker, and parentheses stay text.
- Asking: the model lost the Question behind the no-tools note in two live Answers of the eval of 2026-10-31 and answered another; the Question now comes last.
- Eval: a tool name not shaped like a tool's is withheld from the committed summary; in the eval of 2026-10-31 a tool call whose name held a drafted Answer put Answer words in it.
- Scripts: `tower-eval.sh` puts `~/.local/bin` on `PATH`, so `uv` is found in a non-interactive SSH session.
- Asking: handles in any bracket the model writes are read. A group in `[]`, `()`, `{}` or `<>`, nested one deep, of numbers apart by commas, semicolons, spaces, middle dots or `#`, at least one with a `#`, is a handle (`(#5)`, `{#92}`, `[<#3><#4>]`, `[#59##60]`, `[#65·66]`, `[#5, 6]`), and a range `#5–#7` reads as its two ends; `[74]` stays the Seed's marker. In the eval such forms stayed in the text and gave no Pointer. The sidebar's draft shows them as chips.
- Asking: an Answer ends at the chat template's first control token (`<channel|>`, `<|tool_response>`), and an echoed `<system>…</system>` block is left out. In the eval they reached the reader with the model's monologue after them, and an Answer of a token alone counted as answered: a turn with no words left now fails with "The model gave no Answer." The Conversation keeps the cut text, and the draft never streams a token.
- Asking: a request that offers no tools now ends with the note that says so, after everything the model read, instead of stating it among the instructions. The live agent's sixth request called a tool anyway in all 8 eval turns that reached it, so they failed, and the baseline called tools it was never offered in 3 of 22 turns. The note is a system prompt part for that request only (Ollama gets a `<system>` user turn) and never joins the Conversation.
- Asking: a chat stream that stalls no longer holds a turn for the OpenAI client's 600 s; it fails after `PE_CHAT_TIMEOUT_S`.
- Scripts: `tower-eval.sh`, `tower-check.sh`, `setup-tower.sh` and `setup-mac.sh` refuse to be sourced. Sourced, their `set -e` and `exit` closed the caller's shell at the first failure, and an SSH session with it. tower-eval says that a missing model is created from the Mac by `setup-tower.sh`, and how to start a full run detached, since the tower has no tmux.
- An optional folder left empty in `.env` (`PE_ZOTERO_STORAGE_DIR=`, `PE_TESSDATA_DIR=`) read as the current folder; it is now unset.
- Parsing: a Citation whose author part and year are linked separately in the PDF (LaTeX natbib) became two Citations of one Reference; it is now one (Wegner fixture: 311 → 153 Citations).
- Parsing: numbers beside an author-year bibliography (margin line numbers, the end of the column to the left) were read as Reference labels; labels are now read only where they number the bibliography.
- Parsing: a one-line bibliography entry that GROBID merged with the next one was not split; the split now also starts an entry at a margin line followed by indented lines, and the first part keeps only its own authors (the Seed: 184 → 185 References).
- Citations: a Citation whose GROBID link points at an entry by other authors was linked to it at low confidence (the Seed: six `Carhart-Harris, 2025` Citations shown with Huxley 1959); GROBID's link now counts only when the entry's first author is one of the surnames the marker prints, else the Citation is Unlinked.
- The `api` and `web` compose services have healthchecks, so `up --wait` and `web` wait until uvicorn answers; the reader check no longer meets a just-started container dropping connections.
