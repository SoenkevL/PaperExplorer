### Added
- Eval: run `20261031T192037Z-f349d1e`, live asked three times per Question and retrieval once after stage 10a, judged (`docs/eval-2026-10-31b.md`): its summary and verdicts in `evals/runs/`. The bar is not met, on Pointer coverage alone (0.69 pooled over 66 live turns, 0.69 to 0.71 per repeat): 11 of 18 redrafts failed on a tool call or an empty response, leaving those Answers without Pointers. 85% of live Answers are judged grounded and correct, 91% by retrieval; the Support threshold stays 0.70.
- Asking: an Answer from the whole Seed that gives no handle, yet has a sentence for a Pointer to bear out, is asked once more for its handles: one request without tools or thinking, the first draft as the model's response, then a note for that request only. Its draft becomes the Answer; if it fails or leaves no words, the first Answer stands. A "The Seed does not say …" sentence, and the one after it on what the Seed covers nearby, need none. The stream sends `redraft` (`RedraftEvent`, typed in `ApiClient`), the sidebar empties the draft and says Pointers are being added, `AnsweredEvent.redrafted` says whether the redraft stood, and the trace gets a `redraft` span and the metadata `redrafted`.
- Settings `PE_CHAT_TEMPERATURE` (0.5), sent with every chat request, and `PE_CHAT_ANSWER_THINKING` (false): a request that offers no tools (the whole Seed's, retrieval's last, the redraft) runs without thinking, through `reasoning_effort: "none"`, the switch Ollama was found to honour on the tower. Both go on the trace's metadata and into the eval's run record.
- Eval: `paperexplorer eval --repeat N` asks each Question live N times, each in a fresh Conversation, and by retrieval once. The bar pools the live turns, with each repeat's values and their spread beside it; each turn records its repeat and whether it was redrafted; `RunInfo` records the temperature, the thinking switch and the repeats. Verdicts are keyed by Question, mode and repeat (`Verdicts.share(mode, repeat)`); summaries and verdicts of runs that asked once read as repeat 1.
- Eval: run `20261031T140751Z-a758bbc`, the first with whole-Seed answering live, judged (`docs/eval-2026-10-31.md`): its summary and verdicts in `evals/runs/`. Live read the whole Seed on all 22 turns; the bar is not met, on Pointer coverage alone (0.797); 82% of live Answers are judged grounded and correct against 36% by retrieval; the Support threshold stays 0.70.
- Asking: a Question about a Seed that fits is answered from the whole Seed (ADR 0010). `AskingContext.reading` is `auto` by default, as the API, the CLI's `ask` and the web ask: the whole Seed when its Chunks' bge-m3 tokens fit `PE_WHOLE_SEED_MAX_TOKENS` (40000, kept below `PE_CHAT_NUM_CTX`), else retrieval as before. The whole-Seed request is the eval's baseline unchanged: no tools, no forced search, the trace tagged `whole-seed`. Traces carry the metadata `reading`, and `AnsweredEvent` and `ErrorEvent` say which reading the turn used. While no step shows, the sidebar's reply says it is waiting.
- Setting `PE_WHOLE_SEED_MAX_TOKENS` (40000): the largest Seed, in bge-m3 tokens, read whole.
- Claude Code: `CLAUDE.md`'s `## Agent skills` routes each kind of request (feature, build, bug, design, terms, prototype, research, PR review, conflict, human-only step, agent docs) to the mattpocock skill to call, and names the slash commands to offer the user. `scripts/skill_nudge.py`, a `UserPromptSubmit` hook in `.claude/settings.json`, reminds Claude Code of that list when a prompt asks to add, build, fix, design or review something. `docs/agents/` configures the skills for this repo: GitHub Issues as the tracker (PRs into `dev` say `Closes #<n>`; `docs/design-*.md` are the earlier specs), the five default triage labels, single-context domain docs.
- Eval: verdicts and the eval report (`docs/eval-2026-10-29.md`). Every Answer of an eval run is judged against the Seed, grounded and correct with a note, in `evals/runs/<run id>.verdicts.yaml` (the judge's words only), with each Pointer's place read for aptness; `paperexplorer.evals` loads them, holds them to the run's summary and posts them as Langfuse scores `judge.grounded` and `judge.correct` on each turn's trace (`scripts/post_verdicts.py`, `eval` environment). `Tracing.score_trace` scores a trace by its id; scoring it again replaces the verdict. Committed: the summaries and verdicts of runs `20261029T191529Z-94e980b` and `20261029T202214Z-2b41752`.
- Setting `PE_CHAT_TIMEOUT_S` (120 s): a chat request whose stream stays silent that long fails the turn.
- Eval: the harness for the eval of asking the Seed. `evals/seed-questions.yaml` holds 22 Questions written from the parsed Seed (its measurements, methods, shortcomings and follow-ups, and five it does not answer), each covered one with the places, Heading Path and page, a good Answer points at, as a pydantic-evals dataset. `paperexplorer eval <zotero_key>` asks each in a fresh Conversation as the reader does and, as a baseline, with the whole Seed in context; traces go to Langfuse's `eval` environment tagged with the run id. It measures hit@8, Pointer coverage and Support, Pointers on expected places and their cosines, exact Quotes checked against the printed text, whether uncovered Questions are said to be uncovered, model requests, tool calls and latency, and checks the design's bar. The full report goes to `data/eval/<run id>/`; a summary without the Seed's or the Answers' words, with every trace id, to `evals/runs/` for commit. `scripts/tower-eval.sh` runs it on the tower. `asking`: `AskingContext.tags` adds tags to each Question's trace, `AskingContext.whole_seed` is the baseline (every Chunk in context under its handle, no tools), and `AnsweredEvent` and `ErrorEvent` carry their trace's id; the live mode is unchanged.
- Web: the Conversation sidebar. A Work's page shows the sidebar left of the reader (a drawer below 92rem) with a legend of its two marks. A Question posted there streams through the web app (`POST /works/{id}/questions`, then `GET /questions/{id}/stream`, which relays the API's events as HTML for htmx's SSE extension, vendored at 2.2.4): the tools the model runs, the draft with its handles as placeholder chips, then the resolved Answer in its place, earlier Questions and Answers kept above. Each sentence of an Answer ends with a chip per Pointer, coloured by its Support; an exact Quote is set in the authors' type and links to its place, any other is marked not exact; all model text is escaped. Clicking a chip or an exact Quote scrolls the reader to the place, highlighting its sentence strongly and the rest of its Chunk faintly, its Citations still links. The first Question starts the Conversation; a forgotten one is replaced and the sidebar says so; a Work not embedded is not asked. tower-check asks the Seed one Question through the running web app and logs its counts.
- API: Conversations. `POST /works/{id}/conversations` starts one about a Work whose Chunks are embedded (404 unknown Work, 409 not yet chunked or embedded); `POST /conversations/{id}/questions` streams a Question's turn as server-sent events (`step`, `delta`, then `answer` with its Pointers and Quotes, or `error`), 404 for an unknown or evicted Conversation and 409 while it still answers; closing the stream cancels the turn. Conversations live in the API's memory, evicted least recently used beyond `PE_CONVERSATIONS_MAX` and after `PE_CONVERSATION_IDLE_MINUTES` unused. Turns run on an asking thread with an event loop and a store connection of their own, so the API stays responsive. `ApiClient.start_conversation` and a streaming `ApiClient.ask` yield typed events. compose passes `PE_LANGFUSE_RELEASE` into the containers; tower-check asks the Seed one Question over the running API and logs its event counts and timings.
- Asking: the answering agent. `asking.ask(ctx, conversation, question)` answers a Question about the Seed with pydantic-ai against Ollama's OpenAI-compatible endpoint (`PE_CHAT_BASE_URL`, `PE_CHAT_MODEL`, `PE_CHAT_API_KEY`, `PE_CHAT_NUM_CTX`) and streams its steps, its draft and then the resolved Answer, or an error. The Seed's map (headings with § numbers, its abstract) and the versioned system prompt are always in context; the server's forced first search goes into the history as the model's own; the model reads with `search`, `read_section`, `read_around`, `reference` and `citing_sentences`; a Chunk keeps its `[#n]` handle for the whole `Conversation`; at most 6 model requests, the last without tools; the model's thinking is traced, never shown or kept. One `question` trace per Question holds the forced search, every model request, tool and embedding call and the resolution, scored with the Answer's counts, tool calls, model requests and latency. `paperexplorer ask <zotero_key> "<question>"` streams an Answer and lists its Pointers and Quotes. `scripts/paperexplorer-chat.Modelfile` and `setup-tower.sh` create the `paperexplorer-chat` alias; tower-check asks the Seed three Questions and logs their counts.
- Asking: `asking.resolve_answer` turns a model's complete draft into the Answer the reader sees: its `[#n]` handles leave the text, each handled sentence gets a Pointer per cited Chunk with close or weak Support (bge-m3 cosine against the Chunk sentences, moving to another Chunk read this turn when only that one is close), and words in double quotation marks are an exact Quote only where a Chunk read this turn prints them (ligatures, line-break hyphens and whitespace folded for matching only), mapped to their place in the block. `Answer.counts()` gives Pointer coverage, Pointers per Support and exact and not-exact Quotes for the `question` trace. Setting `PE_SUPPORT_THRESHOLD` (0.7, provisional until the eval).
- Retrieval: `retrieval.search` ranks a Scope's Chunks (for now one Work, the Seed) by the Embedder's Vectors (HNSW, cosine) and by English full text over any stem of the query, fused by RRF (k=60) in one SQL query; each result keeps both rankings' rank and score. `paperexplorer search <zotero_key> "<text>" [-k N]` lists them with page and Heading Path; tower-check runs five searches of the Seed.
- Embeddings: the `Embedder` port with `OpenAICompatibleEmbedder` (any OpenAI-compatible `/v1/embeddings`, Ollama's bge-m3 in use; batches of `PE_EMBEDDING_BATCH_SIZE`, each one embedding observation in the current Langfuse trace) and `FakeEmbedder` for tests (hashed bag of words); migration 0004 with `chunk_embeddings` (one Vector per Chunk with its model's name, deleted with its Chunk, HNSW cosine index); the `embed` Stage after `chunk` (`paperexplorer run embed <zotero_key>`), traced as `stage.embed`, which tower-check runs on the Seed.
- Chunks: `chunking.chunk` cuts a parsed Work's paragraphs and footnotes into Chunks of at most 400 bge-m3 tokens at sentence borders, windows of one paragraph sharing a sentence, flagged `short` or `oversized_sentence`; migration 0003 with the `chunks` table and its English full-text index; the `Chunks` repository; the `chunk` Stage (`paperexplorer run chunk <zotero_key>`), which tower-check runs on the Seed.
- Tracing: `tracing.configure_tracing` sends traces to the tower's Langfuse, or to Langfuse Cloud when the tower does not answer; `Tracing.trace` opens a trace whose name, session, tags and metadata reach every model call inside it. `paperexplorer trace-check` sends one and says where it went.
- `compose.langfuse.yaml`: Langfuse v4.71.0 on the tower, about 6 GB of RAM, its project initialised with the `PE_LANGFUSE_*` keys; the tower wizard sets it up as stage 8.
- `scripts/langfuse_prune.py` keeps the tower's traces under 6 GB on disk, oldest first; `scripts/sync_langfuse.py` copies a time window of traces and scores from Langfuse Cloud to the tower.
- Design for asking the Seed Questions: `docs/design-asking.md`, ADR 0008 (a model may answer; words count as the authors' only when they match exactly), ADR 0009 (pydantic-ai), the Conversation terms in `CONTEXT.md`, and point 6 of v1's definition of done.

### Changed
- Asking: reading the whole Seed, the request closes with one user turn, the note that there are no tools, then "The reader's Question:", then the Question, instead of the note as a turn of its own after the Question; the Conversation keeps the bare Question. The prompt version is now `0a13920d8363`.
- Eval: its modes are `live` (as the reader asks: the whole Seed when it fits) and `retrieval` (forced, the fallback); the bar is checked on `live`, with hit@8 from the forced search. `paperexplorer eval`'s `--baseline/--no-baseline` becomes `--retrieval/--no-retrieval`, on by default. Each turn records its reading, and the summary counts each mode's turns by reading. `AskingContext.whole_seed` is gone; committed summaries of earlier runs still read.
- API: `ApiClient` takes any HTTP client with a fitting `get` rather than an `httpx.Client`, since pydantic-ai brings httpx2 and Starlette's `TestClient` then is an `httpx2.Client`.
- `Tracing.span` and `Tracing.score` record a step and a score under the current trace (nothing outside one); `configure_tracing`'s `http` also carries Langfuse's own requests.
- API: `create_app(connections, asking)` takes the asking setup (`Asking`: each turn's context and the Conversations); without it the app serves Works and Citations only. `HttpClient` also needs `post` and `stream`. `app_from_env` configures logging from `PE_LOG_LEVEL` and `PE_LOG_FORMAT`.
- Asking: `PROMPT_VERSION` hashes the agent's notes (`LAST_REQUEST`, `WHOLE_SEED`, `NO_TOOLS`) with the system prompt, so editing a note changes the version too. `PE_SUPPORT_THRESHOLD` stays 0.7, now set from the eval rather than provisional.

### Fixed
- Asking: in a Seed that numbers no Reference, a bare `[13]`, `[13, 14]` or `[13–15]` in square brackets is read as a handle; the model wrote such numbers for `[#n]` in the live app and the Answer got no Pointer. In a numbered Seed `[12]` stays its marker, and parentheses stay text.
- Asking: the model lost the Question behind the no-tools note in two live Answers of the eval of 2026-10-31 and answered another; the Question now comes last.
- Eval: a tool name not shaped like a tool's is withheld from the committed summary; in the eval of 2026-10-31 a tool call whose name held a drafted Answer put Answer words in it.
- Scripts: `tower-eval.sh` puts `~/.local/bin` on `PATH`, so `uv` is found in a non-interactive SSH session.
- Asking: handles in any bracket the model writes are read. A group in `[]`, `()`, `{}` or `<>`, nested one deep, of numbers apart by commas, semicolons, spaces, middle dots or `#`, at least one with a `#`, is a handle (`(#5)`, `{#92}`, `[<#3><#4>]`, `[#59##60]`, `[#65·66]`, `[#5, 6]`), and a range `#5–#7` reads as its two ends; `[74]` stays the Seed's marker. In the eval such forms stayed in the text and gave no Pointer. The sidebar's draft shows them as chips.
- Asking: an Answer ends at the chat template's first control token (`<channel|>`, `<|tool_response>`), and an echoed `<system>…</system>` block is left out. In the eval they reached the reader with the model's monologue after them, and an Answer of a token alone counted as answered: a turn with no words left now fails with "The model gave no Answer." The Conversation keeps the cut text, and the draft never streams a token.
- Asking: a request that offers no tools now ends with the note that says so, after everything the model read, instead of stating it among the instructions. The live agent's sixth request called a tool anyway in all 8 eval turns that reached it, so they failed, and the baseline called tools it was never offered in 3 of 22 turns. The note is a system prompt part for that request only (Ollama gets a `<system>` user turn) and never joins the Conversation.
- Asking: a chat stream that stalls no longer holds a turn for the OpenAI client's 600 s; it fails after `PE_CHAT_TIMEOUT_S`.
- Scripts: `tower-eval.sh`, `tower-check.sh`, `setup-tower.sh` and `setup-mac.sh` refuse to be sourced. Sourced, their `set -e` and `exit` closed the caller's shell at the first failure, and an SSH session with it. tower-eval says that a missing model is created from the Mac by `setup-tower.sh`, and how to start a full run detached, since the tower has no tmux.
- An optional folder left empty in `.env` (`PE_ZOTERO_STORAGE_DIR=`, `PE_TESSDATA_DIR=`) read as the current folder; it is now unset.
- Parsing: a Citation whose author part and year are linked separately in the PDF (LaTeX natbib) became two Citations of one Reference; it is now one (Wegner fixture: 311 → 153 Citations).
- Parsing: numbers beside an author-year bibliography (margin line numbers, the end of the column to the left) were read as Reference labels; labels are now read only where they number the bibliography.
- Parsing: a one-line bibliography entry that GROBID merged with the next one was not split; the split now also starts an entry at a margin line followed by indented lines, and the first part keeps only its own authors (the Seed: 184 → 185 References).
- Citations: a Citation whose GROBID link points at an entry by other authors was linked to it at low confidence (the Seed: six `Carhart-Harris, 2025` Citations shown with Huxley 1959); GROBID's link now counts only when the entry's first author is one of the surnames the marker prints, else the Citation is Unlinked.
- The `api` and `web` compose services have healthchecks, so `up --wait` and `web` wait until uvicorn answers; the reader check no longer meets a just-started container dropping connections.
