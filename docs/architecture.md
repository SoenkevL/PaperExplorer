# Architecture

Vocabulary: module, interface, seam, adapter, depth (see codebase-design skill). Domain terms: `CONTEXT.md`.

## Deep modules in core

Each row is one module with a small interface. Internals (caches, tokenizer, regexes, SQL) stay behind it.

| `evals` | `load_questions(path) -> Questions` (a pydantic-evals dataset), `unknown_places(questions, chunks)`, `run_eval(ctx, work, questions, info, modes) -> EvalReport`, `summarize(report) -> EvalSummary`, `write_run(report, summary, data_dir, summary_dir)`; `ask_turn` asks one Question in a fresh Conversation, `metrics` measures it; `load_verdicts(path) -> Verdicts`, `unjudged(verdicts, summary)`, `post_verdicts(tracing, verdicts)` for the judge's verdicts (see The eval) | asking + store + embedder | `FunctionModel` + real Postgres + `FakeEmbedder` over the small Seed; measurements as pure functions over hand-built turns |

| `pipeline` | `run_stage(ctx, name, work) -> StageResult` over `STAGES`; later `explore(seed_key, …) -> ExplorationReport` | everything, injected via `StageContext` | real Postgres, `InMemoryLibrary`, recorded GROBID |
| `config`, `logs` | `Settings` (pydantic-settings), `configure_logging(settings)` | in-process | — |

Real seams (two adapters each): `Library`, `Embedder`, and the chat model through pydantic-ai's `Model` (OpenAI-compatible in use, `FunctionModel` in tests; ADR 0009). Everything else is a plain function or class; no ports without a second adapter.

## Pipeline

`explore()` is a chain of independent `Stage`s. A Stage is a function `(ctx: StageContext, work: WorkId) -> StageResult`; it reads and writes only through the store, records its status per Work, and is safe to re-run. The chain is a list, so stages can be run singly (`paperexplorer run parse <work>`), reordered or replaced.

- `StageContext` holds the store connection, the settings, the `Library`, the `Embedder` and `Tracing`; `StageResult` holds counts.
- `run_stage` records `running`, runs the Stage in one transaction, then records `done` with its counts, or `failed` with its error and none of its writes kept.
- A Stage that succeeds makes every later Stage pending for that Work, since what they read has changed (a re-parse cascades the old Chunks and Citations away).
- Built so far: `fetch → parse → chunk → embed → extract_citations`. The CLI names a Work by its Zotero key (ADR 0007) and builds the Embedder and tracing from `Settings`.
- `embed` embeds only the Work's Chunks without a Vector from the Embedder's model, so running it again embeds none, and a new model re-embeds them all. Re-chunking deletes the Vectors with their Chunks.

```
Seed:    fetch → parse → chunk → embed → extract_citations → resolve (local) → catalog
Sources: fetch_sources → for each Source: fetch → parse → chunk → embed
On ask:  Registry Check (a Work or one Reference) → resolutions
Then:    embed_citing_sentences → report
```

Sources reuse the Seed's stage functions; going one level deeper later is the same chain on another Work.

## Retrieval

`retrieval.search` embeds the text once and hands the Vector to `Chunks.search`, one hand-written query of CTEs (ADR 0003):

- **Scope** is a set of Works; for now it is built for one Work alone, the Seed (`Scope.of(work)`). Explorations widen it later.
- **Vector ranking:** the nearest `depth` Vectors of the Embedder's model among the Scope's Works, by cosine distance (`<=>`, the HNSW index's operator). `hnsw.iterative_scan = relaxed_order` keeps the index scanning until `depth` of them pass the Scope filter; the ranking then orders them strictly. Score: cosine similarity.
- **Full-text ranking:** the Scope's Chunks whose `text_search` holds any English stem of the text (`plainto_tsquery`, its ANDs turned into ORs), by `ts_rank`. A question's stop words drop out; a text of stop words only matches nothing.
- **Fusion:** RRF with k=60 over both rankings, each `max(k, 50)` deep, so the first Chunks of a search for fewer are those of a search for more. A Chunk without a Vector from the model can still be found by its words. Ties, in either ranking and in the fusion, go in reading order (Work, then position).
- An empty text finds nothing and embeds nothing.
- `paperexplorer search <zotero_key> "<text>" [-k N] [--no-text]` prints the ranking.

## The agent

`asking.ask(ctx, conversation, question)` answers one Question (ADR 0008-0010, `design-asking.md`) and streams `AnswerEvent`s: `StepEvent` (`tool`, `args`), `DeltaEvent` (`text`), `RedraftEvent` (the draft so far is dropped and written again with handles), then `AnsweredEvent` (`answer`) or `ErrorEvent` (`message`), both with the `trace_id` of the Question's trace (None with tracing off), so scores can be added to it later, the `reading` the turn used (None for an error before it chose), the turn's accounting and its forced search. `model_requests` and `tool_calls` are the model's own, counted as each is made, so a failed turn has them too: a redraft's request counts (even one that failed), the forced search is neither. `forced_search` is the forced search's ranked Chunks (`ScoredChunk`s, as the model was shown them; None reading the whole Seed). The trace's `model_requests` and `tool_calls` scores are the same counts. Callers read these from the event, never from `Conversation.messages`; the API does not send them. Only an answered turn joins the Conversation. The turn runs in a task of its own, so its trace stays inside it; closing the stream cancels it.

- **AskingContext** holds the store connection, Embedder, chat model, settings and tracing, plus two fields: `tags`, more tags on every Question's trace (the eval's `run:<run id>`), and `reading` (`asking.Reading`), how a Question reads the Seed.
- **Reading** (ADR 0010): `auto`, the default, reads the whole Seed when `SeedTools.tokens()`, the sum of its Chunks' bge-m3 tokens, is at most `PE_WHOLE_SEED_MAX_TOKENS` (40,000; `Settings` refuses one not below `PE_CHAT_NUM_CTX`), else by retrieval; `whole_seed` and `retrieval` force one, for the eval. The API, the CLI's `ask` and so the web use `auto`. The reading is chosen once per Question, before its trace opens, and goes on it as metadata `reading`.
  - **The whole Seed:** the instructions are the system prompt, unchanged, then a note that no tools and no search apply (`WHOLE_SEED`), then the Seed's title and every Chunk in reading order under its handle (`SeedTools.whole_seed()`), all of them read; the model is offered no tools, no forced search runs, and the trace is tagged `whole-seed`. The Seed's References are not among them. The request's last message is one user turn, `NO_TOOLS`, then `QUESTION_LABEL` ("The reader's Question:"), then the Question, built for that request only: the Conversation keeps the bare Question.
  - **Retrieval:** the Seed's map, the forced search and the tools below.

- **Conversation:** a plain pydantic object the caller holds: `id`, `work`, `messages` (pydantic-ai's, without the model's thinking), `handles` (`[#n]` → `StoredChunk`, given when a Chunk is first shown and kept for the whole Conversation) and `questions` answered.
- **Context:** the system prompt (`asking/system-prompt.md`; `PROMPT_VERSION` is the first 12 hex digits of the SHA-256 of it and of the agent's notes, `LAST_REQUEST`, `WHOLE_SEED`, `NO_TOOLS`, `QUESTION_LABEL` and `REDRAFT`) and the Seed (in retrieval its map), sent as instructions with every request, then the Conversation so far. The map gives the title, every Heading Path prefix the Chunks sit under as a numbered section (`§3`, with its pages) and the Chunks before the first heading, GROBID's abstract (else those under a first heading "Abstract"), up to 1,500 tokens, with their handles. Those Chunks count as read every turn.
- **Tools** (retrieval only; `SeedTools`; each Chunk shown as `[#n] <Heading Path> · p. <page>` and its text, and remembered in the order shown):
  - `search(query, k=8)`: `retrieval.search` over `Scope.of(seed)`, at most 20.
  - `read_section(heading, part=1)`: the Chunks under a § number or a heading (the whole Heading Path, its last heading, or a unique part of that), in parts of about 3,000 tokens; a part that goes on says how to read the next.
  - `read_around(handle, n=1)`: the Chunk and up to 3 neighbours on either side.
  - `reference(handle, marker)`: the Citations a Chunk prints whose marker or Reference label is `marker` (else whose marker contains it), each with its Reference as printed, key, and Citation Link confidence and level, or as an Unlinked Citation.
  - `citing_sentences(reference)`: a Reference by key, printed label or words of its text; every Citing Sentence of it, each under its Chunk's handle; those Chunks count as read.
- **Forced first search** (retrieval only): before the first request, `search(question)` runs (a `forced search` span) and goes into the history as the model's own tool call and its result, after the Question.
- **Requests:** at most `REQUEST_LIMIT` (6) per Question. The sixth offers no tools and tells the model it is the last (`LAST_REQUEST`), so it answers from what it read; a model that still calls a tool ends the turn with an error. The note is a system prompt part added at the end of that request only (`_NoteAfterReading`, in `before_model_request`), after the last tool result, so it never joins the Conversation; Ollama gets it as a user turn in `<system>` tags. Reading the whole Seed, the closing turn above holds its note instead. A call to a tool the request does not offer gets pydantic-ai's retry prompt, which names the tools there are; a second call to the same unknown tool ends the turn.
- **Timeout:** `chat_model` gives each chat request `PE_CHAT_TIMEOUT_S` (120 s) as its timeout, so a stream silent that long fails the turn instead of waiting for the OpenAI client's 600 s.
- **Settings per request:** every chat request goes with `PE_CHAT_TEMPERATURE` (0.5) through the agent's `ModelSettings`. A request that offers no tools (the whole Seed's, retrieval's sixth, the redraft) runs without thinking unless `PE_CHAT_ANSWER_THINKING` is true: `_ThinkingOnlyWithTools`, in `before_model_request`, adds `openai_reasoning_effort="none"` to that request's settings when its `function_tools` are empty, and Ollama gets `reasoning_effort: "none"`, the switch a probe on the tower found it honours (pydantic-ai's unified `thinking=False` sends Ollama nothing; `think: false` is ignored there). A test pins the body on the wire. Both settings go on the trace's metadata and into the eval's `RunInfo`.
- **Thinking:** Ollama returns it as `reasoning`, which pydantic-ai keeps as a thinking part: it is on the request's span in the trace, never in a `delta`, the Answer or the Conversation's messages.
- **Draft:** `delta`s carry the text parts the model streams, each request's cut by `asking.draft.DraftCut`: nothing after gemma's first control token (`<|name>`, `<name|>`), no echoed `<system>…</system>` block, and a trailing `<…` that could start either held until the next delta settles it. The Answer is the last response's text cut the same way (`answer_draft`), resolved with `resolve_answer` against the Chunks read this turn at `PE_SUPPORT_THRESHOLD`, bare `[n]` read as handles where `SeedTools.numbered_references()` is false. The Conversation keeps that cut draft as the response's text.
- **Redraft:** reading the whole Seed, an Answer with no Pointer and no unknown handle, yet with a substantive sentence that neither says what the Seed does not say ("the Seed does not say") nor follows one, is asked once more (`_redraft`): `RedraftEvent`, then one more run of the same agent, at most one request, over the turn's messages (the closing turn, the first draft as the model's response, without thinking parts) and `REDRAFT` as a last user turn for that request only. Its draft, cut and resolved, becomes the Answer, and its response replaces the first in the Conversation; `AnsweredEvent.redrafted` says so. If the run raises (a tool call it was not offered exceeds the one request) or leaves no words, the first Answer stands, and the span's output says why. The turn's `model_requests` counts both runs. The trace gets a `redraft` span (the first draft in, the second out) holding that request, and its metadata `redrafted` turns `true` when the redraft gave the Answer. An Answer with no letter or digit left ends the turn with an error, "The model gave no Answer."; the Conversation stays as before.
- **Model:** `chat_model(settings)` is pydantic-ai's OpenAI chat model with Ollama's provider profile (thinking in `reasoning`, tool schemas without `strict`) at `PE_CHAT_BASE_URL`, model `PE_CHAT_MODEL` (`paperexplorer-chat`, `scripts/paperexplorer-chat.Modelfile`); `PE_CHAT_NUM_CTX` repeats the Modelfile's `num_ctx` for the traces.
- The tools call the store and the Embedder in the event loop: one connection, and the Chunks read in a fixed order. The API therefore runs each turn on a loop of its own (see The API's Conversations).
- `paperexplorer ask <zotero_key> "<question>"` streams the steps and draft, then prints the Answer, its Pointers with their places and its Quotes, and a summary line: the reading, then counts.

## Answers

`asking.resolve_answer(draft, handles, read, embedder, threshold, *, bare_handles=False)` turns the model's complete draft into the Answer the reader sees (ADR 0008, `design-asking.md`). `handles` maps each handle of the Conversation to its `StoredChunk`; `read` are the Chunks the model read in this turn; `threshold` is `PE_SUPPORT_THRESHOLD`; `bare_handles` reads a bare `[n]` as `[#n]`, for a Seed that numbers no Reference.

- **Handles** are `[#n]`, and every group of `[]`, `()`, `{}` or `<>`, nested one deep, that holds only numbers, at least one with a `#`, apart by commas, semicolons, spaces, middle dots or `#`: `[#n, #m]`, `(#n)`, `{#n}`, `[<#n><#m>]`, `[#n##m]`, `[#n·m]` and `[#n, m]` read as `[#n][#m]`, and a range `#n–#m` (any dash) as its two ends. A group without `#` (`[74]`) stays text, unless `bare_handles`: then a group in square brackets, nothing nested inside, is a handle too (`[13]`, `[13, 14]`, `[13–15]`), while `(5)`, `{5}` and `<5>` stay text. The web app's `answers.Draft` reads the same grammar (without bare handles, since it cannot know the Seed's citation style); `tests/fixtures/handle-forms.json` is the table both are tested with. Handles leave the Answer's text with the spaces before them (a handle that starts its line takes the whitespace after it), so every offset counts into the text the reader sees. A handle belongs to the sentence it stands in, or the one whose full stop it follows. A handle the map does not know is dropped and listed in `Answer.unknown_handles`.
- **Sentences** end at `.`, `!` or `?` (perhaps inside closing quotes or brackets) before whitespace and a capital, and at every line break.
- **Pointers:** each Chunk a sentence cites gives one Pointer, in the order cited. The sentence's Vector is compared with each Chunk sentence's (the Chunk's own spans): the cited Chunk's closest sentence if its cosine clears the threshold (close); else the closest sentence of another Chunk read this turn if that one does (close, and the Pointer moves there); else weak, at the cited Chunk's closest sentence. Pointers of one sentence that reach the same place are one. A Pointer carries its place (`block_id`, `start`, `end`), its Support, its Chunk (`chunk_id`, `chunk_start`, `chunk_end`, for the faint highlight) and the cosine (`similarity`).
- **Embedding:** the cited sentences and every sentence of the cited and read Chunks go to the Embedder in one call, each distinct text once; an Answer without handles embeds nothing. Inside a `question` trace the call records itself.
- **Quotes** are the words between double marks, straight or curly, closed on the same line; single marks stay prose (the closing one is also the apostrophe), and inside a Quote they are its words. Each Quote is searched in every Chunk read this turn, the Chunks its sentence points at first, at word boundaries, with ligatures spelled out, a hyphen between letters (with any whitespace after it) and soft hyphens dropped, and whitespace runs as one space; for matching only. A match is an exact Quote with its place in the unfolded block text (`block_id`, `block_start`, `block_end`); `exact` follows from that place, so no Quote is exact without a match. Punctuation the model put inside the closing mark stays outside an exact Quote when the authors' text goes on without it.
- **Counts** (`Answer.counts()`, the `question` trace's scores): sentences, substantive sentences, Pointer coverage (substantive sentences with a Pointer over all substantive ones; none without any), Pointers close and weak, Quotes exact and not exact, unknown handles. A sentence is substantive unless it is a question, ends in a colon, or has under four words.

## The eval

`paperexplorer.evals` measures how well the Seed's Questions are answered (`design-asking.md`, Eval). `paperexplorer eval <zotero_key> [--questions evals/seed-questions.yaml] [--no-retrieval] [--only <name>…] [--repeat N] [--run-id …] [--summary-dir evals/runs]` runs it; `scripts/tower-eval.sh` runs that on the tower.

- **The Question set** (`evals/seed-questions.yaml`) is a pydantic-evals dataset: each case is a Question (`inputs`) named `<kind>-<topic>`, with its kind (`measurement`, `method`, `shortcoming`, `follow-up`, `uncovered`) and the places a good Answer points at (`metadata`). A place is a Heading Path and page exactly as `chunk` gives them; an uncovered Question lists none, a covered one at least one. Before asking anything, the command refuses places at which no Chunk of the Seed sits, and a Work not chunked and embedded by the Embedder's model.
- **A run** asks every Question in each mode, one at a time, each in a fresh Conversation: `live` (`Reading.AUTO`, as the reader asks), `RunInfo.repeat` times (`--repeat`, 1 by default), a whole pass per repeat, and `retrieval` (forced, the fallback; `--no-retrieval` leaves it out) once. Runs before ADR 0010 asked `retrieval` (then the live agent) and `baseline` (the whole Seed); `Mode` still reads their summaries. pydantic-evals runs the cases (`max_concurrency=1`) and `AskingMetrics` measures them. Traces go to Langfuse's `eval` environment, whatever `.env` says, named `question` and tagged `run:<run id>`; the run id is the start in UTC and the commit (`20261029T140512Z-57a4348`).
- **A turn** (`ask_turn`) records its repeat, the reading it used (from its last event), whether its Answer is a redraft (`AnsweredEvent.redrafted`; that request counts among the model's requests), the Answer, its trace and Conversation ids, each Pointer's sentence, Support, cosine and place (with the Chunk sentence it matched), each Quote's words, exactness and place, the model's requests and tool calls (`model_requests` and `tool_calls` from its last event; the forced search not among them) and its tools, the latency and the time to the first delta. A turn that read by retrieval has its search's `Hit`s from the event's `forced_search`, the Chunks the model was shown.
- **Measured** (`metrics`; booleans become pydantic-evals assertions, numbers scores): `hit_at_8` (a Chunk of the search sits at an expected place) and `first_hit_rank`; `pointer_coverage`, `pointers_close`, `pointers_weak`; `pointers_on_expected` (share of the Pointers at an expected place) and `places_pointed` (share of the expected places pointed at); `quotes_exact`, `quotes_not_exact` and `quotes_verified` (every exact Quote's words are the printed text at its place, folded on their own: ligatures, soft and line-break hyphens, whitespace); `says_not_covered` for uncovered Questions (a heuristic: "the Seed does not say …" and its kin); `unknown_handles`, `model_requests`, `tool_calls`, `latency_s`. Places and hit@8 count for covered Questions only.
- **Outputs.** The full report goes to `<PE_DATA_DIR>/eval/<run id>/`: `report.json` (every turn, Answers and the Seed's words included), `answers.md` (each Answer with its Pointers' places and matched sentences, its Quotes and metrics, for reading against the Seed), `summary.json` and `summary.md`; `scripts/tower-eval.sh` adds `console.log`. The summary also goes to `evals/runs/<run id>.{json,md}`, to be committed: the run's commit, model, prompt version, `num_ctx`, chat temperature, thinking switch, live repeats, Embedder, Support threshold and Question set hash; the bar for the live mode, its turns pooled, with each repeat's value and their spread (`BarCheck.per_repeat`, `spread`) when asked more than once (hit@8 ≥ 0.8 from the forced search, the live mode's if it searched, else the retrieval mode's; Pointer coverage ≥ 0.8; no Quote marked exact that is not; the judged Answers left to the judge); each mode's aggregates over all its turns (`ModeSummary`: repeats, redrafted turns, and `by_repeat` each repeat's bar values), with its turns counted by reading; the Pointers' cosine quantiles and buckets by Support and by where they landed; and per Question its places, the search's places, and per mode a list of its turns, each with its repeat, reading, whether redrafted, metrics, Pointers (sentence, Support, cosine, place, on an expected place), tools and trace id. No words of the Seed or of an Answer: the Seed's licence is unknown. A tool's name not shaped like one (word characters, at most 40) is withheld with a marker, since the model once sent a call whose name was a drafted Answer (trace 448b0aa1). Summaries of runs before repeats, one turn per mode, read as repeat 1.
- **Verdicts.** `evals/runs/<run id>.verdicts.yaml` (`Verdicts`) holds a judge's verdict per turn (Question, mode and `repeat`, 1 by default) on its trace: grounded, correct, a note in the judge's words, and each Pointer read as apt, partly or not; a test holds every committed one to its run's summary (`unjudged`). `scripts/post_verdicts.py` posts them as `judge.grounded` and `judge.correct` (BOOLEAN, the note as comment) to the `eval` environment; a score's id derives from trace and name, so posting again replaces it. `Verdicts.share(mode, repeat=None)` is the bar's judged line: the share of a mode's turns grounded and correct, all repeats pooled or one, a failed turn counting as neither.
- **Aggregates.** hit@8 is the share of covered Questions with a hit; Pointer coverage pools the substantive sentences of the covered Questions' Answers, since an uncovered Question's "The Seed does not say …" is substantive and rightly unpointed.

## API contract

The API returns structured JSON only, never HTML: a Work as an ordered list of blocks (heading path, page, bbox, text) with Citation spans as character offsets into the block text, plus endpoints for Evidence by Citation and Scope. Any frontend renders from this; the HTMX web app is the first consumer.

- `GET /works`: every Work's Library Item snapshot and each Stage's state (`pending`, `running`, `done`, `failed`).
- `GET /works/{id}`: the snapshot plus `blocks[]` in reading order; each block has `citations[]` of `{id, start, end, confidence_level}` (`certain`, `high`, `low`, `unlinked`). 404 until the Work is parsed.
- `GET /citations/{id}`: the Citation's marker, Citing Sentence and `text_origin`, its Citation Link (`confidence`, `evidence`, `confidence_level`) and the Reference as printed with the fields read from it; both null for an Unlinked Citation.
- Offsets count Unicode code points (Python `str` indices), not UTF-16 units. Spans may overlap or coincide: a printed range's dash stands for several Citations.
- `paperexplorer_api.schemas` imports nothing from core, so the web app depends on the contract alone.
- `POST /works/{id}/conversations`: starts a Conversation about a Work whose Chunks are embedded; 201 with `{id}`. 404 for an unknown Work; 409 while the Work has no Chunks, or any Chunk lacks a Vector from the API's Embedder model (`detail` says to run `chunk` and `embed`, or `embed`). Conversations live in the API's memory until Postgres and login replace that store (see The API's Conversations).
- `POST /conversations/{id}/questions` with `{text}` (not blank, else 422): 404 for an unknown or evicted Conversation (start a new one); 409 while it is still answering a Question; else 200 and a `text/event-stream` of `asking`'s `AnswerEvent`s. Each SSE event is named by its `type` and carries the event as JSON data (`event: delta` / `data: {"type": "delta", "text": "…"}`); after 15 s without an event the API sends a `: ping` comment, so the stream stays open while the model thinks.
  - `step` `{tool, args}`: a tool the model runs, with its arguments; the forced first search comes first. A Question that reads the whole Seed has none.
  - `delta` `{text}`: more draft text, handles and all; the Answer replaces the draft.
  - `redraft` `{}`: the draft gave no handle and is dropped; the model writes its Answer again with them, and the `delta`s that follow are that new draft.
  - `answer` `{answer}`: the resolved Answer, the turn's last event. `text` is the draft without its handles, which every offset of the Answer counts into; `sentences[]` of `{start, end, pointers[]}`, each Pointer `{block_id, start, end, support, chunk_start, chunk_end}`: the place (`close` or `weak`) and its Chunk's span in the same block, for the faint highlight; `quotes[]` of `{start, end, exact, block_id, block_start, block_end}`, the place null when not exact.
  - `error` `{message}`: the turn failed and ends here; the Conversation stays as it was before the Question.
  - Closing the stream cancels the turn. Offsets count code points, as above.
- The typed client (`paperexplorer_api.client.ApiClient`) mirrors the routes: `start_conversation(work_id) -> Conversation` and `ask(conversation_id, text)`, a generator of the events parsed into `schemas.AnswerEvent`; 404 raises `NotFoundError`, 409 `ConflictError`. It takes any HTTP client with `get`, `post` and `stream` (`HttpClient`), so httpx and httpx2 clients both fit.

## The API's Conversations

- `paperexplorer_api.conversations.Conversations` holds `asking.Conversation`s by id in process memory, and evicts the least recently used beyond `PE_CONVERSATIONS_MAX` (50) and any unused for `PE_CONVERSATION_IDLE_MINUTES` (120). A restart clears them; an evicted Conversation is unknown.
- `paperexplorer_api.asking_thread.AskingThread` runs every turn on one thread with an event loop of its own, beside the API's. The tools call the store and the Embedder synchronously and block their loop meanwhile (seconds while Ollama loads a model), so the API's own loop stays free for other requests and streams. All turns share that loop, since the chat model's HTTP client keeps its connections on the loop that opened them. Each turn opens a store connection of its own through `connections()`. One turn per Conversation at a time; events cross to the request's loop through a queue, and closing the stream cancels the turn on its loop.
- `create_app(connections, asking)`: `Asking(contexts, conversations)` gives each turn its `AskingContext` around the turn's connection, and the store of Conversations. Without `Asking` the app serves Works and Citations only. `app_from_env` builds the Embedder, chat model and tracing once from `Settings`.

## The web app's Conversation sidebar

A Work's page has three panes under a top bar: the Conversation left, the Work on a paper-like sheet in the middle (it scrolls on its own, not the window), the Citation right. Below 80rem the Citation pane is a bottom sheet whose height the reader drags (25–85% of the window); below 64rem the Conversation is a drawer. Floating buttons open them there; the top bar's toggles turn the panes that are columns on and off, and a Citation clicked always shows. `static/panes.js` keeps this, and the theme: `paper` or `night`, CSS custom properties in `style.css`, the system's light or dark until the reader picks one; an inline script in `base.html`'s head applies the stored choice before the stylesheet paints; the toggle is a pressed/unpressed "Night theme" button. The theme, the panes that are on and the sheet's height are kept in `localStorage` (`pe.theme`, `pe.panes`, `pe.sheet`), and the page works without it. Inter, Source Serif 4 and JetBrains Mono are served from `static/fonts/` (variable Latin subsets from @fontsource-variable 5.1.0, SIL OFL), never from a font CDN. Templates link scripts and stylesheets through `static_url`, which appends a hash of the file's contents (`?v=`), so a deploy never leaves a browser running a cached old script.

- **Routes.** The sidebar's form posts `text` and the page's `conversation_id` (empty at first) to `POST /works/{id}/questions`. The first Question starts the Conversation (`ApiClient.start_conversation`) and sends its id back into the form out of band. The response is the Question with an empty reply whose `sse-connect` (htmx's SSE extension, vendored as `static/sse.min.js`) points at `GET /questions/{question_id}/stream`.
- **Pending Questions.** EventSource only GETs, and the Question's text stays out of the URL, so the web app holds each posted Question in memory (`relay.PendingQuestions`, the newest 64) under a random id until its stream route takes it, once. A second GET of the same stream (an EventSource reconnecting) gets an `error` saying to ask again. The slot lives in one process: run the web app with one worker.
- **Relay.** The stream route returns a `StreamingResponse` over `relay.relay`, a sync generator that iterates `ApiClient.ask` inside `contextlib.closing`, so a browser that goes away closes the API's stream and cancels the turn (when the API's next event arrives; the web app's client swallows the API's pings). It re-sends each event as a named server-sent event carrying HTML, one `data:` line per line:
  - `step`: a line naming the tool and its arguments, appended to the reply's steps (none when the Seed is read whole: until the first `delta` the reply shows a waiting line, which CSS hides once the draft has text);
  - `delta`: draft text appended to the draft, handles as placeholder chips (`answers.Draft` holds back a bracketed group still open at a delta's end, nested ones included, until it closes or holds a character no handle has);
  - `redraft`: out of band through the reply's hidden swap target, the draft (`#draft-<question id>`) emptied in place with `hx-swap-oob="innerHTML"`, so its `sse-swap` listener stays and the new draft streams into it, and the line above it (`#redraft-<question id>`) saying Pointers are being added, which also hides the waiting line; the relay starts a fresh `Draft`;
  - `conversation`: the API had forgotten the Conversation (404), so the relay started a new one; out-of-band HTML puts the notice above the reply and the new id into the form;
  - `answer`: the resolved Answer, with the steps folded away; `error`: the turn's message (the API's, or still answering on 409, or a Work not embedded, or a stream that ended or broke off).
  `answer` and `error` replace the whole reply, which holds the `sse-connect`, so htmx closes the EventSource with it and it never reconnects; every stream ends in one of them.
- **The Answer** is cut in Python (`answers.answer_runs`) at its sentences' and Quotes' code-point offsets, so no offset crosses into JavaScript; the template autoescapes every piece of model text, and the Answer renders with `white-space: pre-wrap`, so its line breaks show and no Markdown is rendered. Each sentence ends with a chip per Pointer, numbered across the Answer, coloured by Support: close in the reader's link colour (which its certain and high Citations share), weak in its low colour, dashed. An exact Quote is a link in the reader's serif and link colour; any other Quote has a wavy mark and stays the model's.
- **Clicking a Pointer** (or an exact Quote) runs `static/conversation.js`: it maps the place's code-point offsets onto the block's text nodes, scrolls the reader there, and paints the place strongly and the rest of the Chunk (`chunk_start`–`chunk_end`) faintly with the CSS Custom Highlight API. The block's DOM is left as it is, so its Citations stay links; a browser without the API gets a faint background on the block. It scrolls the Work's sheet, and below 64rem closes the drawer first (a `pane:close` event that `panes.js` handles).
- **Lifecycle:** a 409 when starting the Conversation (a Work not embedded) answers the Question with a refusal and asks nothing; a 404 from `ask` starts a new Conversation and says so; a 409 from `ask` says the Conversation is still answering.

## Tracing

Every model call, chat and embedding alike, runs inside a Langfuse trace and never opens a top-level trace of its own, so a request's calls are found by nesting, not by time.

- **One trace per Question**, named `question`. `session_id` is the Conversation's id; `user_id` stays empty until login. Tags: `asking`, `work:<zotero_key>`, and `whole-seed` when it reads the whole Seed. Metadata: WorkId, Zotero key, the Question's position in the Conversation, prompt version, model, `num_ctx`, temperature, thinking switch, reading, whether redrafted.
- **Inside it:** `forced search` in retrieval (a tool observation, its embedding inside), pydantic-ai's `invoke_agent asking` holding each model request as `chat <model>` (a generation with token usage, its thinking among its output) and each tool call as `execute_tool <tool>`, every embedding call (`embeddings <model>`), and `resolve answer` (the draft in, the Answer's counts out); a redraft adds a `redraft` span holding its `invoke_agent asking`, and a second `resolve answer`.
- **Metadata:** `work_id`, `zotero_key`, `position` (from 1), `prompt_version`, `model`, `num_ctx`, `temperature`, `answer_thinking` (`true` or `false`), `reading` (`whole_seed` or `retrieval`), `redrafted` (`false`, made `true` by `Tracing.add_metadata` on the trace's own span once a redraft gave the Answer). A Question that reads the whole Seed is also tagged `whole-seed`.
- **Scores on the trace,** sortable and filterable: `Answer.counts()` by field name (`sentences`, `substantive_sentences`, `pointer_coverage` when any sentence is substantive, `pointers_close`, `pointers_weak`, `quotes_exact`, `quotes_not_exact`, `unknown_handles`), `tool_calls` (the model's, without the forced search), `model_requests` and `latency_s`. Eval runs add `judge.grounded` and `judge.correct`.
- **Stages:** `embed` traces as `stage.embed`, tagged `pipeline` and `work:<key>`, with one embedding observation per batch (named `embeddings <model>`: the batch's texts, its token usage, the count and length of its Vectors).
- **CLI search:** `paperexplorer search` traces as `search`, tagged `cli` and `work:<key>`, holding the query's embedding observation.
- An embedding call made outside any trace records nothing; with tracing off, `Tracing.embedding` returns at once.
- **Environment** is `development` (Mac), `tower` or `eval`; eval runs keep the name `question`, so live and eval traces compare directly, and add the tag `run:<run id>`. The eval records each trace's id, which `AnsweredEvent` carries, for the judges' scores. The release is the git SHA. The containers have no git: `compose.yaml` passes `PE_LANGFUSE_RELEASE` from the shell into `api` and `pipeline`, and `tower-check.sh` and `setup-tower.sh` set it with `git rev-parse --short HEAD`.
- **Conversations over the API:** each Question is a `question` trace as above, whose `session_id` is the API's Conversation id, so a Conversation's Questions group as one Langfuse session.
- `tracing` builds its own OpenTelemetry tracer provider, never the global one, with environment and release on its resource; instrumentation reaches Langfuse only when handed that provider.

## Testing

Fake what we don't own, run what we do.

- **Pure modules** (`citations`, `chunking`, `parsing`): tests through the interface with fixture PDFs / `ParsedWork`s. Fixtures are CC BY papers (`tests/fixtures/README.md`), plus a synthetic scan and Tesseract's fast English model so OCR runs offline.
- **GROBID**: a service we run, but slow to start, so `parsing` tests read GROBID output recorded per fixture PDF (`scripts/record_grobid_fixtures.py`); one live test per run starts the pinned image with testcontainers and checks fresh output keeps the recorded structure.
- **Postgres**: always real. testcontainers starts a throwaway `pgvector` container on Mac and tower alike, or `PE_TEST_DATABASE_URL` points at an existing empty database; each test runs in a rolled-back transaction (ADR 0005). The fixtures live in the root `conftest.py`, shared by every package and `tests/e2e/`; code that commits (the CLI) gets a scratch database of its own.
- **Zotero, Embedder**: in-memory adapters at the `Library` and `Embedder` seams.
- **Chat model**: pydantic-ai's `FunctionModel` scripts tool calls and text; Pointer and Quote resolution is tested as a pure function over hand-built Chunks and Answers. A bad real Answer becomes a named regression test built from its recorded message history.
- **Tracing**: an in-memory span exporter checks trace names, `session_id`, tags and nesting. Tracing is off in every other test.
- **Web app**: its tests fake the API over `httpx.MockTransport` with JSON and event streams built from `paperexplorer_api.schemas`, and check the HTML (the Answer's marks parsed as XML). That closing the relay closes the API's stream is tested on `relay.relay` directly, since Starlette's `TestClient` reads a stream whole. The browser side (`conversation.js`: highlights by code point; `panes.js`: theme, panes, sheet and drawer, at each width) is checked by hand in a browser; `tests/e2e` runs a Question from the sidebar through the real API with a scripted model.
- **External HTTP** (Crossref, OpenAlex): `resolution` keeps the matching rules in pure functions tested with hand-written cases for the likely and the harmful scenarios (exact DOI, a neighbour's DOI, preprint vs published, alias DOI, missing subtitle, wrong-year near-miss, garbage string, empty result). Resolution tests seed `registry_responses` rows from recorded JSON; the HTTP clients run over `httpx.MockTransport` (batches, 429/5xx, spent budget). HTTP is never live in tests.
- **Regression rule**: every real failure seen in use is kept as a named test with its recorded responses (`registry_responses` rows for resolution) before it is fixed.
- `@pytest.mark.tower`: only tests needing Ollama, a real Zotero account or the GPU.
